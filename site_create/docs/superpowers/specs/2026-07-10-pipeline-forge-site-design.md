# PipelineForge 产品介绍站设计说明

日期：2026-07-10  
状态：已确认视觉方向与页面叙事，待用户复核书面规格

## 1. 目标与受众

网站的首要目标是推动访客在 Codex 中启用并开始使用 PipelineForge。核心受众是处理 DataEngine、DataHub、COT、HBase、ClickHouse、报表和数据库 DDL 的数据工程师及技术负责人。

成功标准：访客在首屏理解产品价值；能在一分钟内辨认五类能力；清楚从哪里启用插件；在桌面和移动端都能顺畅浏览；动效提升理解但不妨碍阅读或操作。

## 2. 品牌与视觉方向

采用用户选定的 **Liquid Glass** 方向：明亮背景、大面积留白、黑色高对比文字、低饱和蓝紫光晕、半透明玻璃面板和精细阴影。整体接近成熟 iOS 产品发布页的克制与精致，不复刻具体 Apple 页面。

- 使用 PipelineForge 现有 PNG 标识，不重新绘制或篡改品牌图形。
- 字体使用系统字体栈，优先呈现 SF Pro 风格，并保证 Windows 和 Android 的可靠回退。
- 色彩以冷白、石墨黑、系统蓝和少量紫色为主，现有标识中的橙色只用于状态与关键提示。
- 不使用模型生成插画或手写 SVG；主要视觉由排版、CSS 光晕、玻璃层级和真实产品内容构成。

## 3. 页面叙事与结构

采用用户确认的“产品发布式叙事”，单页滚动完成完整介绍。

1. **悬浮导航**：标识、能力、工作流、可靠性、启用插件。滚动后保持轻量玻璃效果。
2. **首屏**：主标题“把数据工程，锻造成确定性。”；说明从需求文档到可运行代码的端到端价值；主按钮“在 Codex 中启用”；次按钮“探索能力”。右侧为可交互 Pipeline 玻璃卡片。
3. **价值带**：以短句强调“需求可读、诊断可查、代码可运行、变更可审计”。
4. **五项核心能力**：
   - 需求文档转开发说明
   - 数据任务日志诊断
   - 数据同步项目代码生成
   - 报表项目代码生成
   - 多数据库 DDL 生成与转换
5. **端到端工作流**：文档 / 日志 / Schema 输入，经 PipelineForge 处理，输出开发说明、诊断结论、项目代码和 DDL；以滚动驱动的流程高亮呈现。
6. **可靠性说明**：突出可审计产物、运行语义验证、现有模板复用、默认不连接数据库和不执行 SQL 等安全边界。
7. **最终 CTA**：再次提供启用入口，并给出手动查找插件的明确备选步骤。
8. **页脚**：PipelineForge 名称、当前插件版本和简短定位。

## 4. 交互与动效

- 首屏 Pipeline 卡片根据指针位置产生轻微倾斜和高光位移；触屏设备仅保留自动漂浮，不依赖悬停。
- 流程节点以克制的顺序点亮表示“输入 → 理解 → 生成 → 验证”。
- 内容区进入视口时使用小幅上移与透明度过渡；不做大尺度视差，避免眩晕和性能问题。
- 能力卡片支持键盘焦点、触控按压和鼠标悬停，交互反馈保持一致。
- 尊重 `prefers-reduced-motion`：关闭倾斜、漂浮、滚动揭示和连续光效，信息仍完整可见。
- 启用按钮优先尝试 `plugin://pipeline-forge@personal`；页面同时常驻“在 Codex 中搜索 PipelineForge”的手动备选说明，避免自定义协议不可用时形成死路。

## 5. 内容原则

文案以中文为主，英文仅用于短标签和技术名词。所有功能描述来自 PipelineForge 当前插件清单，不宣称插件没有的能力。避免空泛的“AI 驱动”表述，改用具体输入、输出和约束建立可信度。

## 6. 技术结构

使用 Sites 提供的 vinext 单页结构：

- `app/page.tsx`：页面语义结构与轻量交互。
- `app/globals.css`：视觉系统、响应式布局、动效与无障碍状态。
- `app/layout.tsx`：站点标题、说明、Open Graph 与 X 分享元数据。
- `public/`：PipelineForge 品牌标识与经过核验的分享卡片。

不使用持久化、登录、外部 API 或服务端数据库。页面只需要极少客户端状态：导航展开状态、复制反馈和指针驱动的视觉变量。各区块用清晰组件边界组织，但不为一次性内容引入不必要的抽象。

## 7. 响应式与无障碍

- 桌面首屏采用双列构图，移动端改为文案在上、交互卡片在下。
- 触控目标至少 44×44 像素；正文对比度达到 WCAG AA；焦点环清晰可见。
- 使用语义化标题、导航、按钮和链接；装饰元素对辅助技术隐藏。
- 页面在 320px 宽度下不产生横向滚动，关键 CTA 在常见手机首屏后半段可见。

## 8. 异常与降级

- 自定义插件协议无法启动时，访客仍能看到并复制手动启用说明。
- JavaScript 关闭时，所有介绍内容、锚点和启用说明仍可访问；只失去装饰动效。
- 品牌图加载失败时显示文本品牌名，不影响导航和 CTA。
- 分享卡片若生成文本不准确或不可读，则不发布该图片元数据，避免使用错误素材。

## 9. 验证范围

- 运行生产构建并修复实际编译错误。
- 验证导航锚点、主次 CTA、复制反馈和移动菜单的键盘操作。
- 检查桌面、平板和手机断点的内容顺序、溢出与触控尺寸。
- 检查 reduced-motion 模式和无 JavaScript 的内容降级。
- 核对页面出现的五项能力、插件名称、版本和安全边界与当前插件资料一致。
- 构建成功后通过 Sites 私有发布，并交付可访问网址。

## 10. 明确不做

首版不包含登录、在线代码执行、文件上传、真实任务运行、数据库连接、用户数据收集、多语言切换或多页面文档系统。这些能力会分散安装转化目标，也超出当前插件介绍站的必要范围。
